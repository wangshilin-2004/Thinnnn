## 1. 先仲裁一处冲突：体重涨跌用什么颜色？

调研报告里存在一个真实的产品分歧：

| 观点 | 依据 | 取值 |
|---|---|---|
| A. 中文炒股语境"涨红跌绿" | Apple HIG Color 页配了两张同款股票图做对照，中文版上涨用红 | 下降 → 红 `#FF3B30`，上升 → 绿 `#34C759` |
| B. 目标达成语境 | 这是一个**减脂**应用，减重是好事 | 下降 → 绿 `#30D158`，上升 → 橙 `#FF9F0A` |

### 决策：采用 **B（目标达成语境）**，并做两条加固

**理由**：
1. "涨红跌绿"是**股票**语境（红色=涨=资产增加=好）。本项目的语境是**减脂**，减重才是目标达成。照搬股市配色会让"体重下降"显示为警示红，与产品情绪直接冲突。
2. 这与本项目的核心设计目标（ADR-004：**防止用户在体重波动时焦虑弃用**）背道而驰。在用户第 3 天看到体重上涨 0.5kg 时，红色会放大恐慌；橙色是"注意，但不危险"的正确语气。
3. **上升用橙不用红**：体重上涨不总是坏事（可能是增肌、生理期、盐分摄入），红色（danger）语气过重。

**加固 1 —— 方向色随目标动态翻转**：
```
朝目标方向 = #30D158（绿）  |  背离目标方向 = #FF9F0A（橙）
```
用户目标是减脂 → 下降绿；用户目标是增肌 → 上升绿。语义始终是"你正在赢"，而不是硬编码某个方向。

**加固 2 —— 强制第二编码（这是 HIG 的硬要求，不是可选项）**：
HIG 原文："**Avoid relying solely on color to differentiate between objects, indicate interactivity, or communicate essential information.**"
所以体重变化永远同时显示 **颜色 + 箭头（↓↑）+ 带符号数值（−0.3 / +0.5）**。这样色盲用户可读，也顺带解决了方向色本身的歧义。

> 这条决策**可逆**。如果用了两周觉得别扭，改一个 CSS 变量即可（`--data-trend-good` / `--data-trend-bad`）。

## 3. 字体：一条法律红线

**SF Pro 不能用于网站。** 授权原文限定只能 "solely for creating mock-ups of user interfaces to be used in software products running on Apple's iOS, OS X or tvOS"，并明确禁止 "create, develop, display or otherwise distribute any documentation, artwork, **website content** or any other work product"。Apple Design Resources 许可同口径。

**我们的方案**：
```css
--font-sans: -apple-system, BlinkMacSystemFont, "Inter Variable",
             "PingFang SC", "Hiragino Sans GB", "Microsoft YaHei UI",
             "Source Han Sans SC", system-ui, sans-serif;
```
- `-apple-system` / `BlinkMacSystemFont`：调用**访问者本机已安装**的 SF Pro，不涉及分发字体文件，**合规**。在 Mac + Safari 上开发看到的依然是真 SF Pro，效果不打折。
- `Inter Variable`：自托管（SIL OFL 1.1，`@fontsource-variable/inter`），给非 Apple 设备一致的观感。选它不选 Geist 的原因：Inter 为屏幕小字号做过优化（`opsz` 光学尺寸轴），且字重梯度足够做 `Display 96px / Ultralight` 级别的粗细对比；Geist 字重只有 400-700。
- 中文字体**只做 fallback，不主动下载**（思源黑体动辄 5-10MB，对首屏是灾难；用户设备上的苹方/微软雅黑已经很好）。

**中文排版的三个硬约束**（这是中英混排最容易翻车的地方）：
1. **中文字距必须归零**。Inter 每 100px 宽度排 11.2 个字符，中文只有 6.25 个——把英文字体的负字距套到中文上，字会挤成一团。`--tracking-display: -0.02em` 只作用于纯英文/数字。
2. **中文字重降一档**。Apple 标题常用 600，中文用 600 会显得糊且重，降为 500。
3. **中文行高 ≥ 1.5**（西文常用 1.2-1.3）。

**数字必须 `font-variant-numeric: tabular-nums`**。体重、热量这些数字会实时跳动，等宽数字才不会让整行左右抖动。

## 4. 主题切换机制（第一天就要做对）

**决策**：`<html class="dark">` 的 class 策略 + `localStorage` + **阻塞式内联脚本**。

```html
<!-- 放在 <head> 最前面，必须阻塞渲染 -->
<script>
  (function () {
    var t = localStorage.getItem('theme');
    if (t === 'light') document.documentElement.classList.remove('dark');
    else document.documentElement.classList.add('dark');   // 默认深色
  })();
</script>
```

**为什么不用纯 CSS 的 `prefers-color-scheme`**：我们需要**手动切换**（用户在深色环境下也可能想用浅色），媒体查询无法被用户覆盖。

**为什么必须有那个内联脚本**：如果等 React 加载完再切换主题，页面会先闪一下白（FOUC，Flash of Unstyled Content）。内联脚本在 HTML 解析到 `<head>` 时就执行，比任何外部资源都早。这是这个方案唯一的正确打开方式，代价是它**不能被打包器优化**，必须内联。

**Tailwind v4 对接**：v4 用 `@theme` 定义 Token 即自动生成工具类，不需要 `tailwind.config.js`。深色变体用自定义 variant：
```css
@custom-variant dark (&:where(.dark, .dark *));
```

## 5. 玻璃质感（Liquid Glass 的网页近似）

苹果 WWDC25 的 Liquid Glass 网页端**能还原约 90%**，配方是四层叠加，缺一层就没有"苹果味"：

```css
.glass {
  background: rgba(28, 28, 30, 0.72);
  backdrop-filter: blur(24px) saturate(180%);   /* ① 模糊 + 提饱和 */
  border: 1px solid rgba(255, 255, 255, 0.10);  /* ② 1px 亮边 */
  box-shadow:
    inset 0 1px 0 rgba(255, 255, 255, 0.12),    /* ③ 顶部内高光 */
    0 12px 32px rgba(0, 0, 0, 0.60);            /* ④ 投影 */
}
```

**约束**：
- **同屏玻璃元素 ≤ 3 个**。`backdrop-filter` 是 GPU 密集操作，堆多了在 iPhone 上直接掉帧。
- **不要在 `backdrop-filter` 元素上加 `will-change`**，会强制持续合成。
- 真正的折射/色散效果需要 SVG `feDisplacementMap`，**不建议做**——性能代价远大于观感提升。
- 必须写 `@supports not (backdrop-filter: blur(1px))` 的降级（不支持的浏览器用不透明背景）。

## 6. 图表规范（差异化主战场）

**选型：Recharts 3**（理由：苹果风图表是 SVG 的活——圆角柱、渐变面积、圆头细折线在 SVG 里是原生属性；而 ECharts 203.7 KB 且 Canvas 取不到 CSS 变量，主题切换会失效）。

| 图表 | 形态 | 关键参数 |
|---|---|---|
| 今日热量 | 环形进度 | 圆头 `stroke-linecap: round`，底环低对比 |
| 三大营养素 | 三条圆角横条 | 蓝 `#0A84FF` / 黄 `#FFD60A` / 紫 `#BF5AF2` |
| 体重趋势 | 面积图 | 主线 7 日移动平均 + 渐变 `0.35 → 0` + 原始点小圆 |
| 热量 vs 体重 | 双轴叠加 | **核心差异化图表** |
| 打卡密度 | 热力图 | 日历格 |

**配色约束与第二编码**（因为 `#FF9F0A` 橙 vs `#30D158` 绿对红绿色盲有风险）：
- 三大营养素用**蓝 / 黄 / 紫**——这是红绿色盲下仍可区分的组合，把红绿留给"热量摄入 vs 消耗"这一组对比。
- 每种营养素**额外用形态区分**：蛋白=实心面积，碳水=45° 斜纹，脂肪=点状填充。**靠明度差 + 形态差，不靠色相差**（[Okabe–Ito 色盲友好色板](https://jfly.uni-koeln.de/color/) 思路）。

**通用规则**：
- 网格线**只留水平**，`rgba(255,255,255,0.06)`，或完全去掉
- 坐标轴文字用 `--text-tertiary`，不要让轴喧宾夺主
- 圆角柱 `radius={[4,4,0,0]}`，柱间留 `barGap`
- Recharts 的**柱顶胶囊圆角和柱段间隙必须自定义 `shape`**（`radius` 属性做不到），这是苹果健康图表最显眼的特征，要预留改造成本
- 图表全部走 `React.lazy` 动态导入，首屏不加载 125 KB 的图表库

## 7. 动效

**决策：原生优先，JS 库只负责状态耦合。**

| 场景 | 方案 | 理由 |
|---|---|---|
| 滚动驱动的入场、视差、进度 | **CSS Scroll-driven Animations**（`animation-timeline: scroll()`） | 声明式，跑在**合成器线程**，不掉帧，零 JS 体积 |
| 数字滚动、列表增删、手势 | **Motion**（Framer Motion 14） | 与 React 状态天然结合；约 34 KB |
| hover / focus / 颜色切换 | 纯 CSS `transition` | 零成本 |

**硬性要求**：所有动效在 `prefers-reduced-motion: reduce` 下关闭。滚动驱动动画要**默认显示最终态**（而不是隐藏），这样不支持的浏览器只是"没有动画"，不会出现"内容永远不显示"。

## 8. 移动端适配硬性清单（iOS Safari 专属坑）

这几条不做，手机上就是残废：

- [ ] **`100vh` → `100dvh`**。iOS Safari 的地址栏会伸缩，`100vh` 会让底部内容被地址栏盖住
- [ ] **`padding: env(safe-area-inset-*)`**。全面屏的底部小黑条会盖住底部导航
- [ ] **输入框 `font-size: 16px` 起步**。小于 16px 时 Safari 聚焦会自动放大整个页面，且不会自动缩回
- [ ] **`inputmode="decimal"`**。体重输入要直接唤起数字键盘，不要用 `type="number"`（它有上下箭头且行为不一致）
- [ ] **触控目标 ≥ 44×44px**（HIG 硬要求）
- [ ] **禁用双击缩放**带来的 300ms 点击延迟（`touch-action: manipulation`）
- [ ] **`-webkit-tap-highlight-color: transparent`**，去掉点击时的灰色方块
- [ ] PWA：`manifest.json` + `apple-touch-icon`。注意 **iOS 不支持 `beforeinstallprompt`**，只能靠用户手动"添加到主屏幕"
