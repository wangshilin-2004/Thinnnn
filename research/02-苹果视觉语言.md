# 02 · 苹果视觉语言与设计 Token 规格

> 目的：为「体重 + 饮食可视化管理」网站提供一套**可直接落地**的 Apple 风格视觉方案。
> 本文所有色值 / 字号 / 圆角 / 间距均为具体数值，可直接写入 CSS 变量或 `tailwind.config.js`。
> 检索时间：2026-10-16。凡非 Apple 官方发布的数据，均标注来源与性质。

**一句话结论**：用 **iOS 深色 keynote 风**（纯黑底 + 玻璃卡片 + 系统色）做视觉，用 **Inter + PingFang SC** 做字体，用 **Recharts** 做图表，动效优先用 **原生 CSS scroll-driven animations**，复杂编排才上 Framer Motion。整体只需 4 类 token，全部列在文末速查表。

### 1.3 SF Pro 与 Apple Design Resources 能不能用在网页上？——**不能**

这是本次调研最需要点明的一条。SF Pro 的授权原文规定，字体只能用于**为运行在 Apple 系统上的软件产品制作 mockup**：

> "you may use the Apple Font **solely for creating mock-ups of user interfaces to be used in software products running on Apple's iOS, OS X or tvOS** operating systems"
>
> "you may not use the Apple Font to, **create, develop, display or otherwise distribute any documentation, artwork, website content or any other work product**"
>
> "You may not **embed the Apple Font in any software programs or other products**"

来源：[San Francisco Font License 全文（ScanCode LicenseDB 收录）](https://scancode-licensedb.aboutcode.org/san-francisco-font.html)

Apple Design Resources License 是同样的口径（官方 PDF：https://developer.apple.com/support/downloads/terms/apple-design-resources/Apple-Design-Resources-License-20230621-English.pdf ）：

> "you may not use the Apple Design Resources to create, develop, display or otherwise distribute any documentation, artwork, **website content** or any other work product"

**结论**：
1. **不要自托管 SF Pro，不要用 `@font-face` 引 SF Pro 的 woff2。** 你的网站属于 "website content"，明确在禁止范围内。
2. **可以用 `-apple-system / BlinkMacSystemFont`**。这是调用访问者本机已授权安装的系统字体，不涉及分发字体文件，和 `font-family: Arial` 同理。你在 Mac + Safari 上开发时看到的依然是真 SF Pro，效果不打折。
3. **不要在 Figma 里用官方 SF Pro 模板直接产出网站视觉稿再发布截图**——严格说也踩线。自用做参考没问题。

### 1.4 免费替代字体：**Inter**（首选），Geist 次之

| 字体 | 授权 | 与 SF Pro 的接近度 | 结论 |
|---|---|---|---|
| **Inter** | SIL OFL 1.1（[LICENSE.txt](https://raw.githubusercontent.com/rsms/inter/master/LICENSE.txt)） | 最高。同为中性 grotesque，x-height 与字重梯度几乎对齐 SF Pro；**Inter 自带 `cv05`/`ss03` 等 OpenType 特性可微调 `1`/`l`/`a` 的字形**，能进一步逼近 SF | ✅ 首选，`@fontsource-variable/inter@5.3.0`（OFL-1.1） |
| **Geist** | SIL OFL 1.1（[LICENSE.txt](https://raw.githubusercontent.com/vercel/geist-font/main/LICENSE.txt)） | 中高。Vercel 出品，几何感略强于 Inter，气质更"科技发布会"，但字重少、中文缺字多 | 🟡 备选，`geist@1.7.2`（SIL OPEN FONT LICENSE） |
| 思源黑体 / Noto Sans SC | SIL OFL 1.1 | 中文字形与 PingFang 同源（同为 Source Han 家族或相近设计），是中文兜底正解 | ✅ 仅作 fallback，不主动下载 |

**为什么 Inter 而不是 Geist**：Inter 是当年为「屏幕小字号可读性」专门优化的（动态 optical size `opsz` 轴 + 手动 hinting 调优），17px 正文下的清晰度明显更好；Geist 的字重梯度窄（主要为 400/500/600/700），做 Apple 式"Semibold 标题 + Regular 正文"的两级层次够用，但做 `Display 96px / Ultralight` 这种级别的粗细对比会不够。而且 Inter 有 `@fontsource-variable` 包，按需子集化最省流量。

## 2. Keynote 视觉特征拆解 → 可编码的规则

苹果发布会的视觉配方其实只有 6 条，全部可量化：

| 特征 | 可编码规格 |
|---|---|
| 近黑背景 | `#000000`（OLED 纯黑，苹果官网首页实测用色）。**不要用 `#111`/`#0A0A0A`**——纯黑 + 玻璃卡片的层次感最强 |
| 大字号标题 | 主标题 **56–120px**，`font-weight: 600`，`letter-spacing` 接近 0（见 §4 的追踪表修正说明） |
| 居中构图 | 内容容器 `max-width: 980px`（苹果官网正文列宽实测 ≈ 980px），整体 `text-align: center` |
| 大量负空间 | 区块上下间距 **120–240px**（桌面），产品图与文案之间 ≥ 64px |
| 渐变光晕 | 单色径向渐变叠加，`opacity ≤ 0.35`，`filter: blur(80-120px)`，**永不使用彩虹高饱和渐变** |
| 产品图中置 | 图片居中，宽度 60%–100% 容器宽，底部常叠一层同色投影做"悬浮"感 |

### 2.1 Liquid Glass（WWDC25，2025-06-09 发布）

官方发布稿：https://www.apple.com/newsroom/2025/06/apple-introduces-a-delightful-and-elegant-new-software-design/

HIG Materials 页给出的定义是**两个变体**（这是官方原文，可直接引用）：
- **regular**：“blurs and adjusts the luminosity of background content to maintain legibility”——会模糊并调整背景明度以保可读性，绝大多数系统组件用它。**网页上的玻璃卡片对应这个。**
- **clear**：“highly translucent… ideal for prioritizing the visibility of the underlying content”——高度透光，只适合浮在照片/视频上。若背景偏亮，官方建议**在其后加 35% 不透明度的黑色 dimming layer**。

**"液态"的五个光学成分**（来自 [Liquid Glass Effect in CSS and WebGL](https://html-in-canvas.dev/liquid-glass-effect/) 的拆解，属工程社区逆推而非苹果规格）：
1. Translucency + blur — 背景透出并柔化
2. **Refraction** — 玻璃作为透镜**位移**背景，而不只是模糊（这一步是"liquid"与"frosted plastic"的分界）
3. Chromatic aberration — 边缘的色散
4. **Specular light** — 方向性高光 + 更亮的菲涅尔边缘 + 一圈细亮边
5. Motion — 有机的形变与涟漪

**网页端现实结论**：`backdrop-filter` 只能做到第 1 步。**纯 CSS 能做出 90% 的观感，但做不出真正的折射**（`backdrop-filter` 没有位移能力；真折射需要 `feDisplacementMap` SVG 滤镜或 WebGL）。对一个体重管理站，**不建议上 SVG/WebGL 折射**——收益极低、掉帧代价高。用 §3.3 的 CSS 方案就够。

## 3. 色板（全部可直接复制）

### 3.1 表面与文字色

深色是本站主推方案（发布会感），浅色作为日间模式。**全部色值见 §8 Token 速查表**，此处只给语义与选色理由：

- `bg/canvas`：深色用**纯黑 `#000000`**（OLED 更"沉"），浅色用 `#FFFFFF`。
- `surface/card`：深色 `#1C1C1E`、浅色 `#FFFFFF`。**深色下卡片靠亮度差 + 1px 亮边分层，不靠阴影**（黑底上黑阴影等于没有）。
- `text/primary`：浅色 `#1D1D1F`（**暖黑，不用纯黑**，苹果官网正文用色）、深色 `#F5F5F7`。

**对比度实测**（WCAG 公式验算）：

| 组合 | 比值 | 判定 |
|---|---|---|
| `#1D1D1F` / `#FFFFFF` | **16.83** | AAA |
| `#1D1D1F` / `#F5F5F7` | **15.46** | AAA |
| `#6E6E73` / `#FFFFFF` | 5.07 | AA ✅ |
| `#6E6E73` / `#F5F5F7` | 4.66 | AA ✅ |
| `#8E8E93` / `#FFFFFF` | **3.26** | ❌ 正文不达标，仅可用于大字号或图标 |
| `#F5F5F7` / `#000000` | **19.29** | AAA |
| `#98989D` / `#000000` | 7.31 | AAA |
| `#98989D` / `#1C1C1E` | 5.93 | AA ✅ |

> ⚠️ **`#8E8E93` 在浅色模式下只有 3.26:1**，不要拿它写 13px 以下的说明文字；深色模式下放在 `#1C1C1E` 上是 5.22:1，安全。

### 3.3 语义映射建议

**先解决一个容易踩的坑：体重下降用什么色？**

HIG Color 页在 "Consider how the colors you use might be perceived in other countries and cultures" 这一条下，配了两张同款股票图做对照——**英文版上涨用绿色，中文版上涨用红色**（官方图：`color-inclusive-color-charts-english@2x.png` / `...-chinese@2x.png`）。也就是说，在中文语境里「涨红跌绿」才是直觉。

**建议：把"涨跌方向色"和"评价好坏色"拆成两套，不要复用。**

- **方向色**（体重曲线本身、环比箭头）：跟随中文语境，**下降 → `#FF3B30`（红），上升 → `#34C759`（绿）**。但这只在"记录客观事实"的语境里用。
- **评价色**（"你已达成目标"、"连续 7 天超额"）：用 `systemGreen #30D158`，与方向色解耦。
- 无论哪套，**必须叠加非颜色的第二编码**（↓ / ↑ 箭头或 ± 符号）。这是 HIG 的硬要求原文："**Avoid relying solely on color to differentiate between objects, indicate interactivity, or communicate essential information.**"（对色盲用户友好，也顺带解决方向色歧义。）
- 如果这个站只是自己用、且你不觉得"减重=红"别扭，也可以简化：**减重 `#30D158` / 增重 `#FF9F0A`**（橙而非红，避免"红色=危险"的负面暗示）。这条没有标准答案，**决策依据是"你看到红字体重下降时，第一反应是高兴还是紧张"**。

**三大营养素 + 热量的配色**（色盲友好取向）：

| 数据 | 色值（深色模式） | 浅色模式填充 | 形态编码（第二编码） |
|---|---|---|---|
| 热量摄入 | `#FF9F0A` systemOrange | `#FF9500` | 实心圆角柱 |
| 热量消耗 / 运动 | `#FF375F` systemPink | `#FF2D55` | 空心描边柱 或 虚线 |
| 蛋白质 | `#0A84FF` systemBlue | `#007AFF` | 实心面积 + 浅渐变 |
| 碳水 | `#FFD60A` systemYellow | `#FFCC00` | 45° 斜纹填充 |
| 脂肪 | `#BF5AF2` systemPurple | `#AF52DE` | 点状填充 |

三条设计约束（这也是为什么这么选）：
1. **蓝 / 黄 / 紫** 是红绿色盲下仍可区分的三色组合；把红绿留给了热量对比，其它数据不再依赖红绿。
2. **蛋白质用蓝** 是《中国居民膳食指南》语境里最反直觉的一条——但它是"最重要的营养素用最强的系统色"的合理取舍；如果你觉得别扭，**换 `#30B0C7` teal / `#FFD60A` 黄**，避开蓝色。
3. **一定要有第二编码**（填充角度、虚实、圆角柱形 vs 面积图），否则色盲用户读不出营养素构成。参考 [Okabe–Ito 色盲友好色板](https://jfly.uni-koeln.de/color/) 的思路：靠**明度差 + 形态差**，而不是靠色相差。

### 4.3 letter-spacing：一个需要纠正的常见误解

网上流传"Apple 大标题用负 letter-spacing"，**这与官方数据不符**。HIG 的 SF Pro 追踪表（单位 1/1000 em）实测规律是**两端为正、17–20pt 附近最紧**——因为 SF Pro 在 ≥20pt 自动切到 Display 光学尺寸（字距本身更紧），需要**加正追踪**来补偿：

| 字号 | 官方追踪 (1/1000em) | 折合 |
|---|---|---|
| 13pt | −6 | −0.006em / −0.08px |
| 15pt | −16 | −0.016em / −0.24px |
| **17pt** | **−26** | −0.026em / −0.44px ← 最紧 |
| 20pt | −23 | −0.023em / −0.46px |
| 22pt | −12 | −0.012em / −0.26px |
| 28pt | **+14** | +0.014em / +0.39px |
| 34pt | **+12** | +0.012em / +0.41px |
| 48pt | +8 | +0.008em / +0.38px |
| 56pt | +6 | +0.006em / +0.34px |

**但这是 SF Pro 的数值，换成 Inter 后不成立。** Inter 没有动态光学尺寸，字距在各档位基本恒定。所以：

- 拉丁文/数字：**`Display 档用 −0.02em`，`Title 档用 −0.01em`，`Body 及以下用 0`**。这是替代字体的视觉补偿值，**不是 Apple 规格**，需要你按实际渲染微调。
- **中文：`letter-spacing: 0`（或直接不设）。** 汉字是等宽全角方块，而 `letter-spacing` 会在**每个汉字之间**插入间距，包括本应紧贴的标点，中文一加字距立刻变"松垮的排版练习稿"。这是中英混排设计里最常见的一处破坏。
- 唯一例外：**全中文的短标题（≤12 字）可接受 +0.01em ~ +0.02em**，会显得更"郑重"。这是中文排版惯例，非 Apple 规格。

### 4.4 中英混排字体栈（可直接粘贴）

```css
:root {
  --font-sans:
    -apple-system, BlinkMacSystemFont,   /* macOS/iOS：命中真 SF Pro，合法且免费 */
    "SF Pro Text", "SF Pro Display",      /* 已装 SF 的机器 */
    "Inter Variable", "Inter",            /* 自托管兜底（Windows / Android / Linux） */
    "PingFang SC",                        /* macOS / iOS 中文首选 */
    "Hiragino Sans GB",                   /* 旧版 macOS 中文 */
    "Microsoft YaHei UI", "Microsoft YaHei", /* Windows 中文 */
    "Source Han Sans SC", "Noto Sans SC", /* Linux / Android 中文 */
    system-ui, "Segoe UI", Roboto,
    "Helvetica Neue", Arial, sans-serif,
    "Apple Color Emoji", "Segoe UI Emoji", "Noto Color Emoji";
  --font-mono:
    ui-monospace, "SF Mono", "JetBrains Mono", Menlo, Consolas, monospace;
}

html {
  font-family: var(--font-sans);
  /* 中英混排关键三件套 */
  font-synthesis: none;              /* 禁止浏览器伪造粗体，避免中文变"糊" */
  text-rendering: optimizeLegibility;
  -webkit-font-smoothing: antialiased;   /* 深色底上必需：默认渲染在纯黑上会显得过粗 */
  font-variant-numeric: tabular-nums;    /* 数据类站点的关键：数字等宽，滚动时不跳动 */
}
```

**中英混排的三个要点**：

1. **`-apple-system` 永远排第一**。它在 Apple 设备上命中 SF Pro；同时中文自动落到 `PingFang SC`——**这就是中英混排最好看的组合**，因为 PingFang SC 的拉丁部分本身就是为搭配 SF 设计的。
2. **Inter 与 PingFang SC 的视觉匹配度**：Inter 的 x-height 与 PingFang 接近，字重梯度也接近（PingFang 有 Ultralight~Semibold 六档），混排不会出现"英文太轻/中文太重"的断层。这是选 Inter 而不是 Geist/Satoshi 的另一个理由。
3. **数字用 `tabular-nums`**。体重、卡路里这类会随动画变化的数字，必须等宽，否则每帧宽度变化会让整行文字左右抖动。若已在 `body` 上开启，大数字展示处可局部用 `font-variant-numeric: proportional-nums` 让造型更自然。

**自托管 Inter（推荐做法）**：

```bash
pnpm add @fontsource-variable/inter   # v5.3.0, OFL-1.1
```
```js
// main.tsx / _app.tsx
import '@fontsource-variable/inter';                 // wght 轴，约 60KB woff2 子集
import '@fontsource-variable/inter/opsz.css';        // 可选：带 opsz 光学尺寸轴
```

不要用 Google Fonts CDN 引 Inter——多一跳 DNS + 隐私问题，且 OFL 允许自托管。

## 5. 圆角、阴影、间距

### 5.1 圆角

| Token | 值 | 用途 |
|---|---|---|
| `radius/xs` | 6px | 标签、Badge |
| `radius/sm` | 10px | 输入框、按钮（对应 iOS 控件圆角） |
| `radius/md` | 16px | 小卡片、列表项 |
| `radius/lg` | **20px** | 标准卡片（本项目主用） |
| `radius/xl` | **28px** | 大卡片、模态、玻璃面板 |
| `radius/2xl` | 36px | 首屏 Hero 容器 |
| `radius/full` | 9999px | 胶囊按钮、Avatar、环形进度 |

**squircle（连续圆角）**：Apple 用的不是几何圆角，而是超椭圆（superellipse），视觉上"更饱满、更少尖角感"。网页实现有两条路：

```css
/* 路线 A：原生（2026-10 已是 Chrome/Safari 可用，Firefox 尚未落地） */
.card { border-radius: 28px; corner-shape: squircle; }

/* 路线 B：兼容兜底 —— 用伪元素叠加近似超椭圆 */
.squircle {
  position: relative;
  border-radius: 28px;
  background: var(--surface-card);
}
.squircle::after {
  content: '';
  position: absolute; inset: 0;
  border-radius: 36%;      /* 关键：内层更大半径 + 高百分比，视觉上变"连续" */
  background: inherit;
  z-index: -1;
  filter: blur(4px);
}
```

> 实战建议：**路线 A 加 `@supports (corner-shape: squircle)` 包裹，作为渐进增强**；不支持时退化为普通 `border-radius: 28px`——观感差距很小，不值得为它引入任何 JS。路线 B 的伪元素法会污染 DOM 结构，只在你真的追求像素级还原时用。

### 5.2 阴影层级

深色模式下**不要用黑色阴影**（黑底上黑阴影等于没有）。分层靠"亮度差 + 1px 亮边"。浅色模式才用阴影。

```css
:root {
  /* 浅色模式阴影 */
  --shadow/sm: 0 1px 2px rgba(0,0,0,0.04), 0 1px 1px rgba(0,0,0,0.02);
  --shadow/md: 0 4px 16px rgba(0,0,0,0.06), 0 1px 3px rgba(0,0,0,0.04);
  --shadow/lg: 0 12px 32px rgba(0,0,0,0.10), 0 2px 8px rgba(0,0,0,0.04);
  --shadow/xl: 0 24px 64px rgba(0,0,0,0.14), 0 4px 16px rgba(0,0,0,0.06);

  /* 深色模式：用"内发光亮边"代替投影 */
  --glass-inner-hi: inset 0 1px 0 rgba(255,255,255,0.12);
  --glass-outer: 0 8px 32px rgba(0,0,0,0.60);
}
```

**玻璃卡片完整配方**（这是本报告最可直接复用的一段）：

```css
.glass-card {
  position: relative;
  border-radius: 28px;
  background: rgba(28, 28, 30, 0.55);          /* surface/card @ 55% */
  -webkit-backdrop-filter: blur(24px) saturate(180%);
  backdrop-filter: blur(24px) saturate(180%);  /* saturate 是"苹果味"的关键 */
  border: 1px solid rgba(255, 255, 255, 0.10); /* 玻璃的边缘 */
  box-shadow:
    inset 0 1px 0 rgba(255, 255, 255, 0.12),   /* specular 顶部高光 */
    0 8px 32px rgba(0, 0, 0, 0.60);
  overflow: hidden;
}
/* 顶部斜向 specular highlight —— 苹果玻璃的"斜切光泽" */
.glass-card::before {
  content: '';
  position: absolute;
  inset: 0;
  border-radius: inherit;
  background: linear-gradient(
    135deg,
    rgba(255, 255, 255, 0.14) 0%,
    rgba(255, 255, 255, 0.04) 28%,
    transparent 55%
  );
  pointer-events: none;
  z-index: 1;
}
/* 玻璃面板做"多层玻璃"：叠 2–3 层，模糊半径递增、透明度递减 */
.glass-stack { display: grid; }
.glass-stack > * { grid-area: 1 / 1; }
.glass-stack > :nth-child(1) { backdrop-filter: blur(40px) saturate(160%); opacity: 0.35; }
.glass-stack > :nth-child(2) { backdrop-filter: blur(20px) saturate(180%); opacity: 0.55; }
.glass-stack > :nth-child(3) { backdrop-filter: blur(8px)  saturate(200%); background: transparent; }
```

> **性能红线**：`backdrop-filter` 每次滚动都要重算背景采样。**同一屏最多 2–3 个玻璃元素**，且不要给它加 `transition: all` 或让它在滚动中变形。`will-change: backdrop-filter` 会强制提升图层、更卡，别加。

**渐变光晕背景**（首屏用，这是"发布会感"的一半）：

```css
.keynote-hero {
  position: relative;
  background: #000000;
  isolation: isolate;
  overflow: hidden;
}
/* 主光晕：一圈冷色，居中偏上，模拟舞台顶光 */
.keynote-hero::before {
  content: '';
  position: absolute;
  top: -20%; left: 50%;
  width: 120vw; height: 120vh;
  transform: translateX(-50%);
  background: radial-gradient(
    ellipse 50% 40% at 50% 30%,
    rgba(10, 132, 255, 0.28) 0%,
    rgba(94, 92, 230, 0.14) 35%,
    transparent 70%
  );
  filter: blur(80px);
  z-index: -1;
  pointer-events: none;
}
/* 辅助暖光：右下角，制造"双光源"立体感 */
.keynote-hero::after {
  content: '';
  position: absolute;
  right: -10%; bottom: -20%;
  width: 70vw; height: 70vh;
  background: radial-gradient(
    circle at center,
    rgba(255, 55, 95, 0.16) 0%,
    transparent 65%
  );
  filter: blur(120px);
  z-index: -1;
  pointer-events: none;

```

> 光晕三条纪律：**① opacity ≤ 0.30**（超过就变"赛博朋克"，不是苹果）；**② 只用 1–2 个色相**，且都取自系统色；**③ `filter: blur()` 配 `pointer-events: none`**，否则它会吃掉整屏的点击事件。

## 6. 数据可视化：苹果健康 App 的图表特征与选库

### 6.1 Apple 健康 App 图表的 6 个特征

1. **圆角柱状**：柱顶（有时上下都）圆角，圆角半径 = 柱宽 × 0.5（做成胶囊）或固定 4px。绝不出现直角柱。
2. **渐变面积图**：折线下方的填充是**同色相从 `0.35` 到 `0` 的垂直渐变**，不是实色块。折线本身 `stroke-width: 2–3px`、`stroke-linecap: round`、`stroke-linejoin: round`。
3. **环形进度**：`stroke-linecap: round`，起点在 12 点方向（`rotate(-90deg)`），底环为 `rgba(255,255,255,0.10)`。
4. **极简网格线**：只保留**水平**网格线，颜色 `rgba(255,255,255,0.06)`，或干脆完全不要网格线，只留轴标签。
5. **无边框、无背景板**：图表直接坐在页面/卡片背景上，没有独立的图表边框。
6. **注释式交互**：点击某点弹出的是**无边框浮层**（不是 tooltip 箭头框），只显示数值 + 日期，字体 `footnote 13px`。

```css
/* 圆角柱 + 渐变面积的可复用配色 */
.chart-bar      { rx: 4; }                       /* SVG 圆角，或 Recharts radius={[4,4,0,0]} */
.chart-bar-capsule { rx: <柱宽/2>; }
.chart-line     { stroke-width: 2.5; stroke-linecap: round; stroke-linejoin: round; }
.chart-grid     { stroke: rgba(255,255,255,0.06); stroke-width: 1; stroke-dasharray: none; }
.chart-axis-label { font-size: 12px; fill: #98989D; letter-spacing: 0; }
/* 面积渐变：在 <defs> 里定义 linearGradient，stops = 同色 0.35 → 0 */
```

### 6.2 六个候选库对比（含实测数据）

数据来自两份做了实测的 2026 年调研：[RavenClaude charting-library-selection-2026](https://github.com/mcorbett51090/RavenClaude/blob/main/plugins/data-platform/knowledge/charting-library-selection-2026.md)（体积为 Vite 构建后 gzip）、[ArcReel chart-library 调研](https://raw.githubusercontent.com/ArcReel/ArcReel/refs/heads/main/docs/research/chart-library.md)（7 个库在 React 19 + Vite 8 + TS 下的真实落地）。

**同口径体积（"堆叠柱状图 + tooltip"实测量，gzip）**：

| 库 | 实测量 | 渲染方式 | 维护状态 |
|---|---|---|---|
| **visx** | **28.5 KB**（核心 ~15 KB，按包引入） | SVG（D3 原语） | Airbnb 维护，稳定，模块化 |
| Chart.js | 57.0 KB | Canvas | 社区维护，活跃 |
| Plotly.js | 94.6 KB | SVG / Canvas / WebGL | 活跃；科学/3D 强，但全量包 ~3 MB |
| Nivo | 97.8 KB | SVG + Canvas + HTML | 社区维护 |
| **Recharts** | **125.5 KB** | SVG | 周下载 48.9M，React 图表库第一 |
| **ECharts** | **203.7 KB** | Canvas（+ WebGL） | Apache 项目，极活跃 |

**渲染方式的能力边界**（决定你会不会撞墙）：

| 方式 | 舒适区 | 崩溃点 |
|---|---|---|
| SVG（Recharts / visx / Nivo-SVG） | **< 5,000 节点/图** | 超过后重渲染拖垮 INP |
| Canvas（ECharts / Chart.js） | **100,000+ 点** | 无（但 CSS 变量取色要 `getComputedStyle`） |
| WebGL（ECharts-GL / Plotly） | **> 1,000,000 点**或 3D | 无 |

**其它关键事实**：
- **Tremor**：Vercel 于 **2025-01-22 收购**（[Vercel 官方博客](https://vercel.com/blog/vercel-acquires-tremor)），v4 在 2026 年中仍是 beta；**底层就是 Recharts**，所以体积 ≈ Recharts + 150 KB 的 Tailwind 组件层。它的价值在"开箱即用的 KPI 卡片"，不在图表本身。
- **ECharts** 的 `echarts-for-react` 封装有未关的 React 19 类型 issue，且与 Tailwind token 体系冲突：Canvas 渲染取不到 CSS 变量，必须 `getComputedStyle` 解析后传进 option——**这会让你失去主题切换的即时性**。
- **Recharts 的两个已知短板**（对苹果风格有直接影响）：① 柱顶圆角要自己写自定义 `shape`，不能只靠 `radius` 属性做到胶囊效果；② 柱与柱之间的**段间隙**（苹果健康里柱子间有明显的 2–4px 缝）需要自定义。这两条都要动代码。
- Recharts 内建键盘无障碍（[官方 Accessibility 文档](https://github.com/recharts/recharts/blob/main/storybook/stories/API/Accessibility.mdx)），这是它相对 visx 的唯一硬优势。

### 6.3 结论：**Recharts / visx 二选一**

> **React + Tailwind 技术栈（推荐，也是 shadcn/ui 生态默认）→ 用 `Recharts@^3`。**
> **纯 HTML/CSS 或极度在意体积 → 用 `visx` 按包引入（`@visx/shape` + `@visx/scale`）。**
> **明确不推荐：ECharts**（203.7 KB + Canvas 取不到 CSS 变量，主题切换失效）、**Tremor**（Recharts 的包装，多 150 KB 换几个卡片）、**Chart.js**（非 React 优先，渐变面积图不够细腻）、**D3 裸用**（对小站是过度工程）。

理由（按权重）：
1. **苹果风格图表是 SVG 的活儿。** 圆角柱、渐变面积、`stroke-linecap: round` 细折线、圆头环形——SVG 里是原生属性，Canvas 里全是手写路径。
2. **Recharts 的体积劣势对本项目不构成问题。** 125.5 KB gzip 可通过 `React.lazy` / 只在图表页加载降到首屏零成本。
3. **visx 的 28.5 KB 要付出"自己写一切"的代价**（圆角柱、渐变、tooltip、响应式容器），迁移成本约半天到一天——除非你已经很熟 D3。
4. **生态一致性 > 绝对最优。** Recharts 是 React 图表库周下载第一（48.9M），shadcn/ui 的 `chart.tsx` 就基于它，能直接用你自己的 Tailwind token 上色。

**已知短板**：Recharts 的**柱顶胶囊圆角**和**柱间段间隙**都要自定义 `shape`，不能只靠 `radius` 属性——这两条恰好是苹果健康图表最显眼的特征，需要预留改造成本。

**落地配方**：
```bash
pnpm add recharts@^3
```
```jsx

<BarChart data={data} barCategoryGap="28%" barGap={4}>
  <Bar dataKey="protein" fill="var(--color-protein)" radius={[4,4,0,0]} />
</BarChart>

// 渐变面积图
<defs>
  <linearGradient id="gWeight" x1="0" y1="0" x2="0" y2="1">
    <stop offset="0%"   stopColor="#FF375F" stopOpacity={0.35} />
    <stop offset="100%" stopColor="#FF375F" stopOpacity={0} />
  </linearGradient>
</defs>
<Area type="monotone" dataKey="weight" stroke="#FF375F"
      strokeWidth={2.5} strokeLinecap="round"
      fill="url(#gWeight)" />
```

## 7. 动效

### 7.1 四种实现方式的取舍

| 方案 | 适用 | 取舍 |
|---|---|---|
| **纯 CSS（transition / @keyframes）** | hover、focus、展开、颜色切换 | 零成本零依赖；但**不能由滚动位置驱动** |
| **CSS Scroll-driven Animations**（`animation-timeline: scroll()` / `view()`） | **首推**：滚动驱动的入场、视差、进度条、透明度渐变 | 声明式、**跑在合成器线程不掉帧**、零 JS 体积。[caniuse 支持度](https://caniuse.com/mdn-css_properties_animation-timeline_scroll)已可用，但**必须给不支持的浏览器留降级**（默认显示最终态，而不是隐藏） |
| **Framer Motion（现 Motion）** | React 状态耦合动效：数字滚动、列表增删、手势拖拽、共享布局 `layoutId` | 约 34 KB；与 React 状态天然结合，是做"数字滚动"最省事的路径 |
| **GSAP + ScrollTrigger** | **复杂时间线**：多元素按秒编排、pin 住某段滚动、SVG 路径绘制 | 最强的时间线控制与滚动同步；代价是额外体积 + 命令式生命周期，与 React 同用要小心清理 |

### 7.2 结论：**原生优先，JS 库负责状态耦合**

> - **滚动驱动的入场 / 视差 / 进度条 / 淡入 → CSS Scroll-driven Animations**（不需要 JS）。
> - **数字滚动（体重 82.4 → 74.2）、列表增删、页面转场 → Framer Motion**。
> - **GSAP 只在你要做"整段 pinned 的发布会式叙事"时才引入**——对一个体重管理站，这个需求大概率不存在。
> - **不要用 `IntersectionObserver` + `requestAnimationFrame` 手写滚动动画**——那是 2020 年的写法，被 Scroll-driven Animations 完全覆盖。

```css
/* 滚动驱动的卡片入场（无需 JS） */
@keyframes riseIn {
  from { opacity: 0; transform: translateY(32px) scale(0.98); }
  to   { opacity: 1; transform: none; }
}
.reveal {
  animation: riseIn linear both;
  animation-timeline: view();
  animation-range: entry 10% cover 35%;   /* 进入视口 10% 时开始，35% 时结束 */
}
/* 降级：不支持时直接显示最终态，绝不留下"内容永远不可见"的坑 */
@supports not (animation-timeline: view()) {
  .reveal { opacity: 1; transform: none; animation: none; }
}

/* 滚动进度条 */

  position: fixed; top: 0; left: 0; height: 2px; width: 100%;
  background: linear-gradient(90deg, #0A84FF, #BF5AF2);
  transform-origin: 0 50%;
  animation: growX linear;
  animation-timeline: scroll(root block);
}
@keyframes growX { from { transform: scaleX(0); } to { transform: scaleX(1); } }
```

**缓动曲线（苹果发布的不是贝塞尔，但网页端这套最接近）**：

| 用途 | 值 |
|---|---|
| 通用 UI 过渡 | `cubic-bezier(0.25, 0.1, 0.25, 1)`（ease） |
| 元素入场 | `cubic-bezier(0.16, 1, 0.3, 1)`（强 ease-out，苹果味最足） |
| 元素退场 | `cubic-bezier(0.7, 0, 0.84, 0)` |
| 弹簧式回弹 | `cubic-bezier(0.34, 1.56, 0.64, 1)`（轻微过冲） |
| 时长：微交互 | 120–200ms |
| 时长：卡片/面板 | 240–320ms |
| 时长：全屏转场 | 400–500ms |

**必须遵守**：`@media (prefers-reduced-motion: reduce)` 下关掉所有滚动驱动动画与数字滚动，只保留 0.01ms 的状态切换。这不是可选项——滚动视差是前庭功能障碍用户的强触发源。

## 9. 落地检查清单

- [ ] 字体：**没有**自托管 SF Pro；栈以 `-apple-system` 开头；Inter 自托管（OFL）；中文 `letter-spacing: 0`、行高 ≥ 1.5
- [ ] 深色模式：`bg` 纯黑 `#000000`，卡片 `#1C1C1E` + 1px `rgba(255,255,255,0.10)` 描边；正文 `#F5F5F7`（浅色模式用 `#1D1D1F`，**不用纯白/纯黑**）
- [ ] 系统色只在深色模式下当文字色用；浅色模式改用 §3.2 的加深版（`#248A3D` / `#D70015` / `#C93400` / `#0040DD`）
- [ ] 体重涨跌：**方向色 + 箭头/± 双重编码**，不单靠颜色
- [ ] 数字 `font-variant-numeric: tabular-nums`
- [ ] 圆角：卡片 20px / 面板 28px；`corner-shape: squircle` 加 `@supports` 渐进增强
- [ ] 玻璃卡片四件套齐全：`backdrop-filter: blur+saturate(180%)`、`inset` 顶部高光、135° 斜向 specular、1px 亮边；同屏 ≤ 3 个，不加 `will-change`
- [ ] 光晕 `opacity ≤ 0.30`，1–2 个色相，配 `pointer-events: none`
- [ ] 图表：Recharts，圆角柱 `radius={[4,4,0,0]}`/自定义 shape，面积图垂直渐变 `0.35 → 0`，网格线只留水平 `rgba(255,255,255,0.06)` 或去掉
- [ ] 动效：滚动驱动用 `animation-timeline`，数字滚动用 Framer Motion；全部在 `prefers-reduced-motion: reduce` 下关闭
- [ ] 触控目标 ≥ 44×44px；内容列宽 980px，正文段落 ≤ 720px
